## 2026-08-15 10:16 初版作成

実際の盤で家族と対局するときの相談役として、単一HTMLのオセロ盤＋着手アシスタントを作成（`othello_20260815.html`）。
CPU対戦はなく、2人で打つ盤に「次の一手」と理由を出す道具として設計。

- 盤は64要素の一次元配列、`1`=黒／`2`=白／`0`=空、手番反転は `3-p`
- 探索はネガマックス＋α-β。中盤6手読み、空き11マス以下は完全読み
- 評価関数＝位置評価表（隅+120／X打ち-40／C打ち-20）＋ `14 ×（着手可能数の差）`
- 音は Web Audio API で全合成。打撃音は物理モデル（接触ノイズ＋円盤の共振＋盤の胴鳴り）、
  BGMはヘ長調3拍子・BPM52の書き下ろし16小節、残響は合成インパルス応答の畳み込み

## 2026-08-16 14:28 EGO-GPT との1人対戦モードを追加

### 要望
- ひとりで遊べるようコンピュータ対戦を追加。強さは初級・中級・上級の3段階
- コンピュータの名前は **EGO-GPT**
- **初級は、ユーザーが勝つようにある程度仕向ける**

### 設計判断
**初級＝「手加減する」実装**（`egoEasy`）。単に浅く読ませるのではなく、意図的に悪手を選ばせた。

- 手加減の強さ `t` を石差に連動：`t = 0.5 + 石差×0.02`（0.2〜1.0にクランプ）
- 評価の符号を反転（`bias = 1-2t`）し、リード中ほど「自分にとって悪い手」を選ぶ
- 隅は取らずに人間に残す（-110×t）、X打ち・C打ちを好む（+55／+26×t）、
  目先の裏返り枚数に飛びつく初心者らしさ（+枚数×3×t）
- **負けているときだけ持ち直す**。理由：64-0のような一方的な展開だと接待が露骨で、
  勝っても面白くないため。接戦にした上で人間が勝つ形を狙う

**中級は当初4手読みで作ったが強すぎたため作り直した。**
2手読み相手に19勝1敗（+37石）となり、初級＝必勝／中級＝ほぼ必敗の段差が大きすぎた。
`深さ／ミス率／ミス時の選択範囲／完全読み開始マス` の5案を各24局で実測し、
**[3手読み・ミス率25%・上位2〜3位から選択・終盤8マス]** を採用（2手読み相手に12勝12敗の互角）。

### この時点の実測（各20〜24局・先後入替）
| | 相手 | 結果 |
|---|---|---|
| 初級 | ランダム着手 | 3勝16敗1分（−13.1石） |
| 初級 | 2手読み | 1勝18敗1分（−15.8石） |
| 中級 | 2手読み | 12勝12敗（−3.3石） |
| 上級 | 4手読み | 12勝0敗（+32.7石） |

### 併せて入れたもの（のちに撤回）
上級を iPhone で成立させるため、探索に**持ち時間と時間切れ打ち切り**を導入し反復深化にした。
→ この方式は 08-16 後半に本人指示で撤回。

## 2026-08-16 14:58 時間切れ打ち切りを廃止／探索エンジン高速化／3モード化

### 本人指示
1. **時間切れ打ち切りはやめて、そこは改善して**（＝速度を時間制限で誤魔化さない）
2. スタート、リスタートのボタンがほしい
3. 市販のオセロ盤と同じ**内枠**（中央16マスの囲み）を入れる
4. モードを **①アシストモード ②ふたりで対局 ③EGO-GPTと対戦** の3択にし、初期値は①。
   ②③を選んだらアシストの選択をすべて外し、対局に必要な項目だけ選ばせる
5. ②③では **・（打てる場所の印）も 〇（最善手の印）も出さない**

### 決定事項 ── 時間切れ打ち切りの撤回
時間で打ち切ると**端末の速さで強さが変わる**（同じ「上級」でも機種によって別物になる）。
打ち切りをやめ、読む深さを固定した上で、探索そのものを速くする方針に変更した。

### エンジン改修の中身
- 盤を `Int8Array` に。1手ごとの盤複製をやめ、返した石を記録して戻す（make / unmake）
- 8方向の並びを事前に表（`RAY`）にし、探索中の配列生成をゼロに
- 置換表（Zobristハッシュ 32bit×2、26万エントリ）で手順違いの同一局面を読み直さない
  ※完全読みと通常読みは値の意味が違うため、ハッシュに区別用の定数を混ぜて別物として扱う
- PVS（最善手だけ広い窓で読み、残りは狭い窓で確認、超えたときだけ読み直す）

**検証**：旧実装と同じ答えを返すことを、深さ4〜5と完全読みで**72局面すべて一致**を確認。

### 速度（開発機・Node基準）
| | 改修前 | 改修後 |
|---|---|---|
| 中盤6手読み（全候補に点数） | 最悪1,637ms | 最悪259ms |
| 中盤7手読み（最善手のみ） | 最悪714ms | 最悪248ms |
| 終盤13マス完全読み | 実質不可（14マスで11秒） | 最悪301ms |

### 固定した読みの深さ
| | 深さ | 完全読み開始 |
|---|---|---|
| アシスト | 7手 | 空き12マス |
| 上級 | 7手 | 空き13マス |
| 中級 | 3手（ミス率25%） | 空き8マス |
| 初級 | 探索なし（手加減ロジック） | − |

上級の1手あたり最長思考時間は開発機で約0.5秒。iPhone でもその2〜3倍に収まる想定。

### UI 改修
- モード3択（既定＝アシストモード）。②③に切り替えるとアシストの選択を全解除し、
  アシスト欄を隠して対局に必要な項目（強さ・石の色）だけ表示する
- ［対局スタート］［リスタート］を追加。**モード・強さ・石の色を変えると開始前に戻る**
  （設定を選ぶ → スタート、という順序を崩さないため）
- **印を出さないモードでは空きマスをすべて押せるようにした**。
  理由：打てる場所だけ押せる状態は、印を消しても「押せるかどうか」が答えになってしまう
  （レビュー指摘 #2 の修正）。置けない場所を押したときは理由を1.6秒表示する
- 市販の盤と同じ内枠：中央16マスを囲む線と、その四隅の打点を CSS で描画。
  石より下（`z-index`）に置き、石を置くと隠れる本物と同じ見え方にした

|---|---|---|
| 初級 | ランダム着手 | 7勝13敗（−8.1石） |
| 初級 | 2手読み | 0勝20敗（−39.0石） |
| 中級 | 2手読み | 9勝11敗（−2.5石） |
| 上級 | 中級 | 8勝0敗（+41.4石） |

### 動作確認
ブラウザで実ファイルを操作し、初期状態（未開始・押せるマス0）→アシストモード→ふたりで対局
（印なし・空き60マス押せる・置けない場所の警告）→EGO-GPT戦（上級で白番／中級で60手フル対局、
62対2でEGO-GPTの勝ち）まで通し、コンソールエラー0件を確認。

## 2026-08-17 実機で出た3件（回転で崩れる／速すぎる／パスで止まる）

### 本人指摘と対応

**① スマホを横にして縦に戻すと画面が崩れ、盤全体が見えない**
スクリーンショットで原因判明＝**iOS が横向きの拡大率を縦に戻しても持ち越していた**（盤がA〜Eまでしか入らず約2倍のまま）。
さらに「縦でも横でも盤全体を常に見せてほしい」との要望を受け、レイアウトを作り直した。

- ページ全体のスクロールを廃止。盤は必ず画面内、あふれる操作パネルだけが内側でスクロール
- 🔴 最初 CSS の `vh` とメディアクエリで切り替えたが、**横向きで盤とパネルが重なる不具合が実機で発生**。
  原因は、ブラウザのツールバーぶんの高さや拡大率のズレを `vh` では拾えないこと
  （開発機の 844×390 では再現せず、実機の「使える高さ 220px」で露見した）
- → **JS が visualViewport の実寸を測って、縦横判定と盤の一辺を px で決める方式**に変更（`fitBoard`）。
  回転直後は端末が古い寸法を返すため 0.12/0.4/0.8 秒後に測り直す
- 実測（すべて盤全体表示・重なりなし・ページスクロールなし）：
  390×844=276px／390×664=276px／375×667=278px／844×390=291px／844×230=131px／667×220=121px

**② コンピュータの着手が速すぎて何が起きたか分からない**
置いた石から近い順に1枚ずつ裏返すアニメーションを追加（1枚0.46秒・間隔0.13秒、9枚以上は0.08秒）。
裏返り音も同じ間隔に合わせた。アニメ中は盤を操作不可、EGO-GPT は返り終わるまで待ってから打つ。

**③ 自分が打てなくなると進まなくなる（本人報告）／「シミュレーションしたのか」**
指摘のとおり、パス局面の通し確認をしていなかった。まず**状態遷移を2万局シミュレーション**したところ、
パスは35%の対局で発生するが「止まる状態」への到達は0。実UIの連続対局でも再現せず。
🔴 **原因を特定できないまま放置せず、どの経路でも前に進む安全網**を入れた。

- `passWatch`：手番側に合法手が無くなったら、メッセージを出して1.5秒後に自動パス
- パス表示を「あなた／EGO-GPT」と名指しに（誰が打つのか分かるように）
- **効果音の例外で対局が止まらないよう `commit` の音処理を try/catch**（iOS で音が出せない状態が有力候補）
- 思考が失敗しても必ず合法手を打つフォールバック
- 検証：パス局面を強制生成して両方向の自動パスを確認／連続6局（パス17回）で停止0・エラー0

### 強さの再調整
| | 変更 | 実測 |
|---|---|---|
| 初級 | 🔴**隅を2個までなら取ってよい**（本人指示）。3個目からは人間に残す | 1局あたり1.13個取る。ランダム相手 9勝14敗、1手読み相手 0勝20敗 |
| 中級 | 3手読み→**2手読み**、ミス率25%→**35%**、**終盤の完全読みを廃止** | 1手読み相手 20勝4敗 → **8勝14敗**。上下関係は維持（上級8勝0敗＞中級15勝1敗＞初級） |

中級で効いたのは深さより**終盤の読み切りをやめたこと**。人が終盤で逆転されるのは、CPU が最後まで
読み切って石数を最大化してくるためだった。

## 未対応・持ち越し

- 候補手の数値の単位が混在（完全読み=石差／通常=内部評価値）→ 表記を分けるか単位を揃える
- `pluckBuffer` のキャッシュキーに音色パラメータが未混入（隅の和音がBGMの音色を再利用しうる）
- 到達不能コード（`doPass`・パスボタン・`playBuf`）の整理
- 対局の保存（リロードで消える）／リスタートの確認ダイアログ
- 検証時に一度だけ、手番の色が入れ替わり自動で手が進む状態を観測した。
  清浄な状態では再現せず（テスト用スクリプトの残留が原因と推定）、`started` のガードを追加して対処。
  実機で同種の挙動が出た場合は、この行を手がかりに再調査する
