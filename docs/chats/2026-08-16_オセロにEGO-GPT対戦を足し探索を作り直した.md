# オセロにEGO-GPT対戦を足し探索を作り直した

## 2026-08-16 セッション

### 要約
8/15に自作した単一HTMLのオセロ対局アシスタント（`othello_20260815.html`）を分析するところから始まり、
仕様の整理 → GitHub Pages 公開 → EGO-GPT（コンピュータ対戦相手）の追加 → 探索エンジンの作り直し →
UIの3モード化まで一気に進めた。iPhone で遊べるようにするのが目的。

経緯は Vault `60_Daily/2026-08-12.md` にあった「実盤で家族と対局する際、黒側のアドバイス役」。
そのためこのアプリは CPU が自動で打たない設計だったが、今回「ひとりでも遊べるように」CPU対戦を追加した。

作業の途中で本人から段階的に要望が入り、そのつど作り直している。
特に大きい方向転換が2つ。①CPU用に入れた「時間切れ打ち切り」を撤回し探索自体を高速化、
②対戦モードではアシスト（・と〇）を一切出さない3モード構成に再設計。

### 決定事項・結論

**公開まわり**
- リポジトリ `TAKE6FAN/othello`（**Public**）。無料アカウントでは Pages が公開リポジトリ限定のため
- コミットの作者メールは `TAKE6FAN@users.noreply.github.com`（Gmail を公開履歴に残さない）
- 公開URL `https://take6fan.github.io/othello/`、ダウンロード用 `.../download.html`

**EGO-GPT（CPU）**
- 名前は本人指定で **EGO-GPT**（別プロジェクトと同名）
- **初級は「手加減する」実装**。浅く読ませるのではなく、評価の符号を反転して悪手を選ばせる。
  隅は取らずに人間へ残す／X打ち・C打ちを好む／目先の枚数に飛びつく
- 初級は2回調整。最終形＝手加減の下限0.8＋隅を取らない。ランダム着手の相手にも3勝27敗（−20.9石）
- 中級は当初4手読みで**強すぎた**（2手読み相手に19勝1敗）ため、5案を各24局実測して
  3手読み＋ミス率25%＋終盤8マス完全読み に変更（2手読み相手に9勝11敗の互角）
- 上級＝7手読み＋終盤13マス完全読み

**探索エンジン（本人指示で方針転換）**
- 🔴 **時間切れ打ち切りは廃止**。理由＝端末の速さで強さが変わってしまうため。
  代わりに Int8Array＋make/unmake、方向走査表、置換表（Zobrist）、PVS で高速化
- 旧実装と同じ評価値を返すことを72局面で全一致確認してから差し替えた
- 中盤6手読み 最悪1,637ms → 259ms。終盤13マス完全読みが最悪301msで可能に

**UI**
- モード3択：①アシストモード（既定）②ふたりで対局 ③EGO-GPTと対戦。
  ②③ではアシストの選択を全解除し、**・も〇も出さない**
- ［対局スタート］［リスタート］を追加。**スタートを押すまで盤に石を置かない**
- 印を出さないモードでは**空きマスをすべて押せる**ようにした。
  打てる場所だけ押せる状態は、印を消しても「押せるかどうか」が答えになってしまうため
- 市販の盤と同じ内枠（中央16マスの囲み＋四隅の打点）を CSS で追加

### 重要なやりとり（原文）

> **TAKE**: いずれも時間切れ打ち切り付きは、やめて／そこは改善して

→ 速度問題を時間制限で誤魔化さず、根本を速くしろという指示。エンジンを作り直した。
この判断基準は他プロジェクトにも効くので記憶に残す価値がある。

> **TAKE**: 初級は、ユーザが勝利するようにある程度仕向ける仕様も盛り込んでほしい

→ 「弱いCPU」ではなく「接待するCPU」。ただし64-0のような一方的な展開は接待が露骨で面白くないため、
当初は負けているときだけ持ち直す設計にした。のちに「もう少し弱く」と言われ、その持ち直しをほぼ削った。

> **TAKE**: 対戦モードでEGO-GPTと対戦時は、・も〇も外してください。ふたりで対戦時も・も〇もはずしてください
> **TAKE**: 対戦モードかアシストモードかを最初にちゃんと判断できるフラグのボタンが必要ですね

→ アシスト機能と対局機能が混ざっていたのを、モードで明確に分ける構成に作り直した。

### 反省・気づき
- 中級の初回設定（4手読み）は**実測せずに決めて強すぎた**。以後は候補を並べて対戦実測で選ぶ手順にした
- 「アシスト・印なし」モードで、印を消しても `disabled` 属性で答えが漏れていた。
  見た目だけ隠して機構を直していなかった典型
- 検証中に一度だけ手番の色が入れ替わる異常を観測。清浄な状態では再現せず（テストスクリプトの残留と推定）、
  `started` のガードを追加して対処。実機で再発したらこの行が手がかり
