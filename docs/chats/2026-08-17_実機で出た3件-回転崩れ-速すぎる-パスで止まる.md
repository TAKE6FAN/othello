# 実機で出た3件（回転崩れ・速すぎる・パスで止まる）

## 2026-08-17 09:11 セッション

### 要約
iPhone で実際に遊んでみて出た不具合3件と、強さの再調整。
前日（8/16）に公開した版を、実機の使用感に合わせて直した回。
**開発機では再現せず、実機ではじめて出た**問題が2件あった。

### 決定事項・結論

**画面（最重要の学び）**
- 横向き→縦向きで盤がはみ出すのは、**iOS が横向きの拡大率を持ち越す**ため（スクショで確定）
- 「縦でも横でも盤全体を常に表示」を満たすため、ページスクロールを廃止し、
  盤を画面に必ず収める構造へ
- 🔴 **CSS の `vh` とメディアクエリによる切り替えは実機で破綻した**。
  ブラウザのツールバーぶんの高さや拡大率のズレを `vh` は拾えず、盤とパネルが重なった。
  開発機の 844×390 では再現せず、**実機の「使える高さ 220px」**で露見
- → **JS で visualViewport の実寸を測って px で決める**方式に変更。6サイズで実測確認

**動き**
- 石が返るところを1枚ずつスローに（0.46秒／間隔0.13秒）。音も同じ間隔に合わせた
- EGO-GPT は、あなたの石が返り終わってから打つ

**止まらないための安全網**
- 状態遷移2万局シミュレーションでは停止0（パスは35%の対局で発生）。実UIでも再現せず
- 原因不明のまま放置せず、**手番側が打てないときはメッセージを出して1.5秒後に自動パス**する
  監視を追加。音の例外・思考の失敗でも止まらないよう保護とフォールバックを入れた

**強さ**
- 初級：隅を2個まで取ってよい（本人指示）。実測1局1.13個
- 中級：2手読み＋ミス率35%＋終盤の読み切り廃止。1手読み相手 20勝4敗 → 8勝14敗

### 重要なやりとり（原文）

> **TAKE**: なんせいつも縦でも横でもスマホの画面にオセロばんは、全部表示してほしいのです。

→ 「はみ出したらスクロールすればいい」ではなく、**常に全部見えること**が要件。
これに合わせてページスクロール自体をやめる構造にした。

> **TAKE**: 横にした時に余計画面が変になった。画面の切り替え方法見直してください。

→ CSS だけで切り替える方式をやめる判断につながった指摘。

> **TAKE**: ちゃんとシュミレーションしましたか？

→ していなかった（パス局面の通し確認をせずに報告していた）。以後、パスのような
分岐は必ず総当たりシミュレーションと実UIの連続対局で確かめる。

### 反省・気づき
- **開発機の画面サイズだけで「実機OK」と判断していた**。iPhone は横向きだとツールバーで
  使える高さが 220px しかなく、そこで初めて崩れた。狭い高さでの検証を標準にする
- **「理屈では起きない」を根拠に安全網を省かない**。2万局のシミュレーションで停止0でも、
  本人は実機で止まっている。再現できないなら、どの経路でも前に進む作りにするのが正解
- 音のような副次処理が本筋（対局の進行）を止めうる構造だった。例外保護を入れた
