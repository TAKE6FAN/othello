# iPhone 15 で盤が画面に収まりきらない（278px→321px）

## 2026-08-21 00:45 セッション

### 要約

本人の指摘は一行。「iPhone15で開いたらスマホ画面にオセロ版が綺麗に収まらない」。
**4日前（8/17）に自分で入れた計算式が原因**だった。回転で崩れる問題を直したときに
入れた「盤は画面の高さの55%まで」という上限が、縦長の画面では効きすぎていた。

### 原因（推測せず実測して特定）

iPhone 15（393×852・Safari で使える高さ 667px）を再現して測った：

| | 値 |
|---|---|
| 使える幅から決まる上限 | 321px |
| **画面の高さの55%から決まる上限** | **278px** ← これが効いていた |
| 実際の盤 | 278px（横に45px余っていた） |

🔴 **「55%」という数字に根拠がなかった**。8/17 は「横向きで盤とパネルが重なる」ことばかり
見ていて、縦向きは「はみ出さなければよい」と安全側に振った割合で済ませていた。
はみ出しは防げても、**余った幅を使い切らない**という別の不満になった。

### 直したこと

- 🔴 **割合をやめた**。「操作パネルに残す最低寸法（縦200px／横290px）を引いて、残りは全部盤」
  という決め方に変更。画面が広ければ盤が素直に大きくなる
- 🔴 **盤の外側にかかる寸法を決め打ちしない**。行番号の列・列名の行・枠を `16/26/19px` と
  書いていたが実際は `18/26/21px`。CSS を触るたびにずれるので、その場で実測して引く
- 🔴 **`viewSize()` に上限を追加**。`visualViewport.height` は回転直後や拡大中に実際より
  大きい値を返すことがあり、そのまま body の高さにすると盤の下がはみ出す。
  版面（`documentElement.clientHeight`）と端末の長辺を超えないように抑えた
- 操作カードを圧縮（次の一手 52→42px、余白と行間）。［対局スタート］がスクロールなしで見える

### 実測（すべて盤全体表示・重なりなし・ページスクロールなし）

| 画面 | 想定 | 盤の一辺 |
|---|---|---|
| 393×667 | iPhone 15 Safari 縦 | **321px**（278 → +43） |
| 393×753 | 同・ツールバー収納 | 321px |
| 393×852 | 同・ホーム画面から全画面 | 321px |
| 852×393 | iPhone 15 横 | 311px |
| 852×320 | 同・Safari 横 | 238px |
| 852×230 | 極端に低い横向き | 150px（下限） |
| 375×553 | 小さい端末 | 257px |
| 1280×800 | PC | 718px |

縦→横→縦の往復で元の寸法に戻ること、対局開始・着手後・EGO-GPT の応手でも崩れないことを確認。

### 検証中に見つけたおまけ

測っている最中に **`--appH`（body の高さ）が 1317px のまま固まる**状態を踏んだ。
`visualViewport.height` が実際の画面より大きい値を返し、それを body に入れた結果。
こうなると盤の下が画面外に出る。**本人が繰り返し報告していた「回転すると盤が全部見えない」の
正体はこれだった可能性がある**。上限を入れたので同じ経路では起きない。

### 反省・気づき

- **前回の修正が次回の不具合になる**。8/17 の「はみ出さないための上限」が、今回の
  「大きくならない」原因そのものだった。安全側に振った固定値は、後で必ず見直す前提で置く
- **割合（%）で頭打ちにしない**。端末の縦横比が変わると意味が変わる。
  引くべきものを引いて残りを使う、という決め方なら比率が変わっても破綻しない
- 決め打ちの寸法（16/26/19px）は実際と 4px ずれていた。**測れるものは測る**
